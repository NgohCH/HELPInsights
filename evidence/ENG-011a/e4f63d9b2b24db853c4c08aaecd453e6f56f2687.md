## Review and recovery

Independent integration-owner review examined the two opt-in switches, per-run 32-byte key, private fixed simulator URL, redirect rejection and request deadline. The review verified that the signature binds the distribution and shared time bucket. The HTTP runtime checks that signature. The trusted SQL submission wrapper receives only a boolean and retains the earlier atomic response logic. Its previous unguarded resolver and writer are no longer granted to the runtime database role. The outage test confirms that ordinary readiness survives a simulator outage while new eligibility verification fails closed.

The first final stack run returned 400 in the existing reporting and response integration tests for empty publication requests with an application/json header. Requiring actual HTTP body framing before reading optional publication settings restored the existing contract. The next run on `helpinsights-test-580af4639cce` passed all Registry tests and failed the unchanged reporting test with `UND_ERR_SOCKET` while other Docker stacks were active. The application logs showed no unexpected restart. The unchanged rerun with no competing test stacks passed reporting and all remaining checks. The malformed-policy case previously created an unintended open link. Rejecting explicit null and requiring JSON framing for supplied options contains that failure before the insertion transaction. PostgreSQL retains the existing irreversible migration ledger semantics. Use a forward fix that preserves distribution modes and their access checks. The predecessor app alone does not understand the new migration or the new resolver grants.

The prototype deliberately permits reuse and sharing until expiry. Eligibility results do not have a person-to-response join, but timing and small cohorts can still permit inference. One-use unlinkable anonymous consumption, production privacy review and a live provider integration remain open.

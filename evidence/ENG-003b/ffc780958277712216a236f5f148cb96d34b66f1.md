## Behaviour verified

- The HTTP test binds each authorization code exchange to the initiating browser, state, nonce and PKCE verifier. Wrong state, missing browser cookie, expired attempt, provider denial and repeat use are rejected. Fixture configuration is refused outside the test runtime.
- Chromium exchanged a code and verified a signed identity token against a local OIDC provider. It rejected invalid issuer, tenant, audience, signature, nonce and expiry, and a valid token without a local binding. PostgreSQL confirmed only the separate identity role can call the session-issuing function.
- A signed-in workspace owner created and published a survey through the UI. A viewer in that workspace was denied creation and publication even with a synthetic elevated role claim. A separate anonymous browser submitted a response. Cookie cross-origin writes were rejected and Live Quiz preserved its bearer-only authoring contract.
- The browser signed out and the revoked credential no longer resolved. Removing an issuer/subject binding invalidated its sessions. The migration test seeded a legacy session on migration 016, upgraded to 017, preserved the legacy session and verified that deleting and re-adding a binding could not revive a previously issued session.

## Defects and independent challenge

- The first focused test failed before the sign-in route existed. An initial Docker attempt failed because the runner had captured its environment before discovering the simulator's browser port. Reinitialising the helper after port discovery repaired startup.
- The first signed-in Chromium run found that a native form navigation could not meet the server's strict origin check for logout. Same-origin Fetch repaired the journey while retaining the server-side origin check.
- The standards and spec reviews found a partially exposed Live Quiz cookie path, insufficient tests of signed token failures, and identity DB readiness that remained green after the issue grant was removed. Host routes now retain their existing bearer contract. Browser and HTTP tests cover denied variants. A real PostgreSQL test reproduced readiness 200 instead of 503, then verified 503 after revoking the grant and 200 after restoring it. Both reviewers checked the frozen source tree again and identified no remaining source blocker for this draft.

## Release boundaries

An approved live Entra app, local identity bindings, Conditional Access MFA evidence, approved test accounts, and reviewed operator settings are still required. The application keeps pending sign-in attempts on a single instance for up to five minutes. Multi-instance deployments need callback routing to the instance that began sign-in and upstream rate limits for the start route. Valid local browser sessions expire after 30 minutes. The application revokes its own session at sign-out. University-only participation and administration sign-in remain separate work. No live accounts, data, production services or protected branches were changed.

## Observed behavior and review

- The optional analytics query uses the same tenant- and role-scoped immutable publication lookup as exports. The browser fixture proved the owner and analyst can read the same specified version. The viewer cannot. Another survey in the same workspace cannot use the existing version identifier, and a different workspace actor is denied. Calls without a version still report the latest publication. Malformed or repeated selection returns 400.
- PostgreSQL showed five responses on version 1 and one on version 2. After closure, Chromium selected each version, displayed its own frozen question wording, and preserved small-cell suppression. The downloaded version 1 CSV contained its historical variable code and exactly five expected rows.
- Independent Standards and Spec review identified the stale default-selection and cross-survey fixture gaps. Requested publications are pinned when loading or exporting. The delayed real download test adds version 3 while an export of version 2 is in flight, then verifies the pinned display through completion. The reporting region also indicates when it is busy.
- The browser request is cancelled when the results panel unmounts. The review confirmed that an archive already queued on the server can still complete. An interrupted download after changing surveys is a separate browser failure-injection check. Long-open workspaces must reload a saved survey to discover versions added by another window.

## Local transport findings

The failures both reported `SocketError: other side closed` with code `UND_ERR_SOCKET`. The failing case moved during the exclusive rerun and the source revision passed on GitHub. A separate native Node loopback exercise with a 7.5-second idle pause returned 200 with both pooled and single-use connections. This did not reproduce the Docker loopback failure. Two probes of a disposable Docker application also opened a fresh loopback socket and returned the expected denial. The intermittent transport cause remains undetermined.

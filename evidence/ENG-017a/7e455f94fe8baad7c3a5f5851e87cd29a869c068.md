## Review and release scope

The recording function writes both fixed events in one transaction and its unique episode/state key covers a retry after a lost commit acknowledgement. The app SQL role can read only the redacted projection under the existing operations policy. The worker role has execute access only to the dedicated recording function for incident recording. Direct app writes cannot specify worker attribution. The default runtime leaves incident recording disabled.

Pending detection lives in one worker process and can be lost if the process stops before recovery. Backoff is capped at 2.4 seconds between polling cycles. This exercise used repeated connection terminations and a separate existing PostgreSQL restart regression. Other transport failures and external notice delivery remain outside this verification. Rolling back to a runtime with earlier schema history requires a compatible build or approved restore. Local verification is focused, with independent review and the full cumulative CI gate still separate.

## Scope and acceptance

ENG-008b covers one requestable capability under ENG-008 and WP-049. It depends on workspace-scoped sessions and survey definitions from ENG-003 and ENG-004. The slice owns the catalogue and review routes, one additive migration, the NPS definition and limits, and the corresponding browser controls and tests.

- A workspace owner or editor discovers NPS authoring and requests anonymous use with a purpose. An explicitly delegated workspace member reviews another member's request.
- Approval and denial record the reviewer, rationale, timestamp, and expiry when approved. Concurrent identical approval by the same reviewer returns the same decision and expiry. A conflicting replay is rejected.
- An unauthenticated caller, outsider, or owner without explicit delegation cannot review. The reviewer fixture is a workspace viewer and can review by explicit delegation alone.
- NPS authoring and publish fail without an active grant. Standard number fields remain available. Expired grants leave already published surveys collecting valid responses.
- PostgreSQL enforces one pending request per workspace and permitted expiry duration. A seeded upgrade preserves the previous migration checksums and stored numeric survey definition.
- The browser journey uses separate creator and reviewer sessions, Enter to approve, and a public respondent in a 390-pixel viewport. Direct SQL proves the actual persisted answer.

## Review and recovery

The integration owner independently reviewed `cd071f2560308cb185def788b4b8a70c8da6a4d7` and found no blocker to a draft PR. The review checked workspace reviewer RLS, separation from the requester, conditional terminal decision writes, and server entitlement checks at save and publication. It raised a request-versus-approval race. Both current mutation routes acquire the same per-workspace transaction lock before callback logic. The request's read of the current entitlement runs after acquiring that lock. Any future mutation path needs to preserve that ordering.

The duration constraint binds recorded expiry to the PostgreSQL decision time and approved duration. Reviewers can decide only while pending and cannot issue reviewer delegations through the application role. Concurrent request or approval paths share a scoped transaction lock. Navigation and approval activation were exercised in Chromium. Screen-reader testing was outside this check.

For recovery, use a forward fix that retains migration history and the published NPS definition reader. Reverting to the predecessor app alone would fail its exact migration-ledger readiness check, and dropping these tables would discard the decision history. Production restoration remains subject to the existing change and recovery policy.

The broader catalogue, reviewer provisioning UI, explicit revocation, notifications, multi-feature policy, and aggregate Net Promoter Score calculation remain open. When integrating with ENG-006 preview, apply the same NPS bounds and numeric form conversion to the shared question fields. No live-provider calls, publishing to GitHub, protected merges or production changes were performed in this worktree.

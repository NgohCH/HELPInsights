## Independent challenge and remaining scope

The integration reviewer examined the operations role, PostgreSQL RLS and
column grants. The reviewer found that the handler held an authenticated
database transaction while waiting for the body. Bounded JSON parsing now
runs before checkout of a connection. Role checks and the insert remain
inside the transaction. The SQL tests were extended to assert that the
application role cannot set audit attribution.

A live runtime database credential is still trusted to set the verified
actor transaction context. Contain a credential compromise using the
database boundary and credential incident process. The deployment and
credential controls need separate review. Deployment, production membership
provisioning, automated recovery and notices, and incident correlation
and retention remain outside this slice. All fixtures were synthetic.

Keep the additive tables to preserve audit history when rolling back.
The preceding runtime expects its exact migration ledger, so rolling
back the app independently requires a compatible build. Restoring an
earlier database requires explicit approval and recovery planning.

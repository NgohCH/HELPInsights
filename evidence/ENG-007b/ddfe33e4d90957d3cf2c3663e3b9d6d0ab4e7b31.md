The deterministic transaction test waits for a known idle-in-transaction backend, terminates only that PostgreSQL backend, confirms the transaction rejects, and queries the fixture actor through the same pool afterwards. The ordinary Chromium survey roundtrip still restarts PostgreSQL, renders results and downloads the JASP-ready archive. In the original Live Poll suite the export worker exited on a checked-out client socket reset during a database restart.

Application authorization and export polling now use one transaction helper. It installs a checked-out Client error listener, preserves the transaction error, and discards the interrupted connection. The pool regains its idle listener before the scoped listener is removed. The independent reviewer confirmed the PostgreSQL driver lifecycle, no implicit write replay and the worker's queue recovery after transaction rollback. The test now keeps its synthetic session credential out of Compose arguments and bounds its wait for the backend to disconnect.

Residual risk remains during migration/provisioning checkout lifecycles, and the deterministic fixture targets the shared application path. The Chromium suite runs real export recovery with the worker, while precise interruption of a checked-out worker mid-archive remains unproven. A lost commit acknowledgement can still leave the caller uncertain whether a write completed. The worker and API use existing durable queue and idempotency rules where available.

Runtime transcripts are local in `runtime-evidence/transaction-reconnect-red.log` and `runtime-evidence/transaction-reconnect-full.log`. The earlier red transcript was redacted before sharing. Rollback means reverting this source commit on the feature branch. PostgreSQL schema stays unchanged.

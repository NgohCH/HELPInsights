## Independent review and remaining risk

Standards and specification reviews of the first candidate raised missing Docker context and ownership validation, false-ready on a stale ledger, migration timeout and ordering, missing rollback and restore evidence, absent secret scanning, and incomplete CI artifacts. Re-review identified an unpinned scanner context and a custom schema search path mismatch. Regression runs observed 200 instead of 503 on ledger tampering and false instead of true for readiness after migration on a custom search path. Tests subsequently passed with migration schema pinning, explicit Docker context, verified test project labels, and captured evidence.

Readiness checks the expected ledger and table existence. An out-of-band column edit with a matching ledger is a remaining blind spot. The operator can detect a schema error from application query failures, contain it by taking the app out of service, and investigate the actual schema and verified backups before restoring. Review database role restrictions and use functional readiness assertions as the survey schema is introduced.

The recovery drill uses bootstrap data in a disposable Docker project. Application workflow, tenancy, survey export, production restore and release validation have separate evidence requirements. GitHub reported no active main rules and no classic protection. Merge and release remain blocked.

## Observed behavior and review

- A creator can publish from saved survey details. The browser requires an explicit public or University selection and binds University publishing to an approved policy UUID. The API checks the displayed draft ETag. A conflicting browser write returns 409 and PostgreSQL retains the first University-only distribution. Reopening the updated draft produces a second University-only distribution.
- Chromium submitted a public response on the new link. PostgreSQL retained that response and published version after the creator ended ordinary collection, and the old link refused further browser access.
- Independent Standards and Spec reviews found that leaving the details panel could lose the one-time link after a committed publish. The test now withholds a successful real HTTP reply while checking that survey and workspace selection and full-page application links are disabled. Releasing the reply displays the new respondent link. Confirmation panels focus their heading and restore opener focus on cancellation.
- An intermediate focused rerun used a label-only workspace locator. The Playwright accessibility snapshot showed a disabled combobox, and the test now addresses it by role and name. The repaired focused run passed both workflows.
- Ordinary survey links close together. Active realtime rooms use their own controls. The latest publication report remains available after closing. Earlier-version reporting and related authorization and export verification are a separate slice. The [acceptance notes](../../docs/progress/SAVED_SURVEY_PUBLICATION_ACCEPTANCE.md) record remaining simultaneous-publish, interrupted browser and cross-link tests.

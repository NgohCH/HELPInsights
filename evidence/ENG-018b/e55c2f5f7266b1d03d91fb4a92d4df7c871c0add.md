## Defects and independent challenge

- The initial checklist tests failed because the command was missing. After an initial implementation, an independent review found omissions in the institutional identity and eligibility prompts. Focused tests reproduced the missing approved tenant, first administrator and eligibility rule prompts and passed after the correction.
- A separately verified checklist receipt could be presented for the wrong release. The operator guide requires the receipt and underlying records to be attached to the exact target and release digest. The command expresses operator attestation and whether it is ready for review. An approved release owner performs activation.
- The independent OAuth review identified missing row-level security on the binding table. Migration 016 now enables row-level security with no application policy. Chromium setup asserted that the application database role has neither SELECT nor INSERT on that table. The restricted resolver uses an explicit binding to an existing principal.
- Chromium verified the user identity and only the authorised workspace, even when signed roles and groups claim elevated or external access. It also verified that removing the binding causes subsequent requests to return 401, an unbound principal is denied, the existing opaque session keeps working and the token cannot open survey routes. Unit tests challenged issuer, audience, signature, time and scope.
- A still-valid bearer can be replayed until expiry or binding removal. The deployment owner must replace the configured public key set and restart for rotation, then verify the new keys against a known valid access token. Scope and local workspace membership constrain requests. A dedicated client allowlist and application-only identities remain future integration work.
- Synthetic evidence leaves live Entra sign-in with MFA, eligible and ineligible University participation, first administrator provisioning, an institutional nonauthor denied in a real University workspace, and partner integration acceptance open. Research Ethics Board clearance and consent remain in the University's external process. No institutional accounts, data, or deployment services were used.

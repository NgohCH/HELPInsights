# User Guide, Contextual Help and First-Run Onboarding

**Audience:** first-time staff and lecturers; separate researcher/operator sections. In-product content must be editable/versioned without code changes for normal content updates.

## Minimum guide

1. Sign in or start an authorised workspace; understand permissions and confidentiality.
2. Click **Create** and select Survey, Pop Quiz, Poll, Feedback, Evaluation or Research.
3. Choose a template or guided blank draft; change the title, audience, survey privacy and response rules.
4. Add, edit and reorder questions and pages; use examples and question tooltips.
5. Preview as mobile/respondent, simulate branches and check score/route results.
6. Run Readiness Check, resolve blocking errors and publish a version.
7. Distribute via link/QR or authorised invitations; explain when an SSO in-app launch is appropriate.
8. Review charts, filter allowed data, export JASP-friendly codebook bundle and manage follow-up events.
9. Close survey, check expiry and download authorised archive before deletion.
10. Get support from contextual help and self-service troubleshooting, without exposing respondent data.

## UI help patterns

- First-run tour **skippable and replayable**; focus on creating first survey.
- Inline `?` help on controls, succinct examples, mini screenshots/short videos as approved assets, searchable topics and accessible keyboard navigation.
- Contextual warnings for privacy and anonymous mode, file uploads, SMS costs, offline devices and research consent.
- Empty states include next-action links; errors state what went wrong, what was preserved and next steps.
- Separate creator, respondent, organisation administrator and platform operator documentation views; role-aware search results.
- Help content entries include `topic_key`, audience, locale, app-version range, reviewed date and URL/route. No false AI-generated help claims.

## Initial user-guide topics

`Create a quick poll`; `Create a scored pop quiz`; `Make a multipage survey`; `Add branching`; `Import template`; `Publish safely`; `Use QR and in-app SSO`; `Export for JASP`; `Retain or delete data`; `Request a feature`; `What self-healing notices mean`.

## Quality bar

Task-based usability test with representative first-time staff: median creation duration, task completion, errors and assistance needed. Documentation acceptance includes tested examples and links, no dead routes, content editable by authorised users and bilingual/multilingual readiness without mandatory translation at launch.

## Starting a live quiz — lecturer guide outline

In **Create → Pop Quiz → Delivery**, select Live Game Show, Classroom Learning, Live Polling or Formal Assessment. Set question timing, score model, optional leaderboard, join/access policy and answer reveal. Preview as host and as student. When ready, choose **Start Live Session**, display the PIN/QR on the lecture screen, wait for students in the lobby and begin. Advance questions and show explanations; pause if necessary. End to review item difficulty, attendance/participation where permitted, session scores and downloadable results. Display practical help for network interruptions, forgotten PIN, late arrivals and privacy implications of public nicknames. Never describe a leaderboard as private if it is projected publicly.
